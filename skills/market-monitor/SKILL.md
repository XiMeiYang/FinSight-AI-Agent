# market-monitor

当前为流程规范；数据、工具与运行环境尚未接入。执行时遵守仓库 [AGENTS.md](../../AGENTS.md)，不能把规划当作已完成的操作。

## 输入

自选股及每股关注方向、涨跌幅阈值、成交量阈值、报告频率，授权数据源、允许延迟、交易会话、规则及版本、计算窗口、冷却时间与当前时间。关键规则未配置时输出缺项和建议，不擅自视建议为已生效配置。

## 工作流程

1. 阅读 [技术方案](../../docs/05-technical-design.md)，校验交易日历、夏令时、停牌及正常交易会话；MVP 不监控盘前盘后，会话外跳过市场检查并记录原因。
2. 检查源时间与采集时间；免费或低成本行情允许 5–15 分钟延迟，不追求高频交易级实时性；在配置允许范围内正常处理并显示延迟，超过新鲜度上限或缺少基准时跳过相关规则并记录原因，不把分钟轮询解释为实时行情。
3. 使用确定性计算执行规则；记录公式、窗口、观测值及阈值。零基数、缺失值、公司行动和乱序数据不得静默处理。
4. 按证券、规则版本及时间窗口去重并执行冷却；恢复后按约定补偿，避免告警风暴。
5. 将符合条件的事件交给已有通知流程；没有已授权投递配置时只形成事件，不发送邮件。

## 输出与边界

输出事件 ID、证券、事件时间、检测时间、来源延迟、告警原因、置信度及其依据、原始来源、规则版本、去重状态和处理结果。有限重试后明确失败；行情不可用时报告监控中断。此 Skill 不自动部署调度器、不持续驻留，也不执行交易。

## 职责与停止条件

按已配置规则覆盖价格、成交量、波动率、行业联动、新闻、公告、财报日期及数据源异常，具体规则见 PRD。重复告警合并并形成简短事件报告，完整收盘报告由 daily-report 负责；数据源异常可记录健康状态，不能伪造市场异动。

规则、阈值或关键基准缺失时停止对应检测并说明；有限重试失败后降级或记录中断。每用户自选股上限待来源额度核验，不能自行写死。未经明确授权不扩展渠道或投递。
