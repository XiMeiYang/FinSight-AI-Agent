## 逐对隔离执行：八项单次诊断

常规输入 N 项会准备 N 个独立请求，每个请求的用户消息只含当前一项主张、它自己的实际入模窗口与来源；系统提示词、JSON Schema、`stream=false` 和 `think=false` 保持不变。`run_model()` 现在拒绝一次送入多项。默认准备模式调用数为 0；显式 `--run-model` 才按顺序逐项请求，本次最多 N 次且不重试。一个检查项的非法输出只让该项失败，不会从无效响应挑出其他结果冒充通过；预检模型缺失或 digest 不符则全部标为未执行。

可复制的**只准备、不调用模型**命令（输入文件仅在本机 Git 忽略目录）：

```bash
PYTHONPATH=src python3 scripts/run_evidence_auditor.py \
  .local_data/reviews/nvda-evidence-auditor-isolated-2026-10-27-001/input.json \
  --output-dir .local_data/reviews/nvda-evidence-auditor-isolated-2026-10-27-001/prepared
```

用户授权的本地运行另加 `--run-model --model qwen3:4b --expected-digest <已核验的 digest>`，并使用**新的空输出目录**。输出按序号分别保存计划请求、实际请求、模型原始响应、结构校验或失败原因、调用次数、digest 与耗时；汇总分开统计已接受、校验失败、运行失败及未执行。真实请求和完整 SEC 窗口只留在 `.local_data`，不上传 Git。

## 范围与运行

2026-10-27，在代码基线 `68608571faeda4c192a81636329b22c5cef01c78` 上增加独立的“主张—单条引用窗口”审计实验。输入必须先由人或其他流程拆成独立检查项；每项有唯一 `pair_id`、主张、原引用 E 编号、**实际入模**的英文窗口和 filing 来源。模块不拆分整份回答，不检索其他窗口或完整申报文件，不接入网页、默认回答路径，也不修改原回答。当前默认生成提示词未改。

服务端要求结果与输入 ID 一一对应，判定只能是 `supported`、`partially_supported`、`unsupported`、`contradicted`、`uncertain`；支持、部分支持及矛盾判定必须附非空英文摘录。摘录只允许折叠空白后与**该检查项自己的窗口**匹配，来源身份由服务端回填。字符串校验只证明摘录出现在窗口中，**不证明语义上支持主张**。缺少提及不等于证据相反。非法 JSON、未知/重复 ID、伪造摘录、超时和截断均明确失败，不重试。主张和证据中的指令均视为不可信文本。

## 八项诊断实测（历史两批）

模型为本机 `qwen3:4b`，digest `359d7dd4bcdab3d86b87d73ac27966f4dbb9f5efdfcc75d34a8764a09474fae7`。固定两批，实际 `/api/chat` **2 次**，无重试；模型报告耗时合计 **20,085 ms**，命令墙钟合计 **20,167.324 ms**。第 1 批结构校验失败，第 2 批通过；因此只有第 2 批四项是被服务端接受的审计输出。两批八项原始结果均保留，不能把失败批次伪装成通过。

第 1 批有一条输出借用了**另一检查项**的英文摘录，服务端检测到摘录不属于本窗口，整批拒绝。另有一条在本窗口找到原文，却将“产能可用性”误判为“组件可用性”：词面校验没有发现这个语义错误。第 2 批通过结构校验，但一条把具体供给风险概括为整个供应链的不确定性，现有初审仅认为部分支持。其余项包括直接支持和不支持的正确示例。完整八项逐条标签、主张、窗口和模型理由只在本地对照表中，不进入仓库。

按保存的原始结果确定性计算：批次通过 **1/2**、失败 **1/2**；八项原始结果没有缺项，逐项结构检查通过 **7/8**、失败 **1/8**，但失败批次仍整体作废。模型原始判定与既有**代理初审**相同 **5/8**、不同 **3/8**；通过批次为 **3/4** 相同。这些是已知问题开发诊断集，既有标签不是人工 gold，数字不是审计准确率。跨窗口错引被拦截；另外两项说明摘录存在也可发生语义错判，且同一模型参与生成与审计可能重复犯错。
