# NVDA 冻结证据提示词单次对照诊断

## 范围与结果

2026-10-27，针对 [NVDA 单份回答证据初审](nvda-answer-evidence-review.md)发现的引用过宽、范围扩大和历史时间表述问题，在代码基线 `fef371f962ef0e2e25854c9379381a97b5051f1c` 上仅修改 `AnswerService` 的系统提示词，进行一次本地对照。候选提示要求要点尽量表达单一事实、每条引用直接支持对应事实、引用精简、概括不超出证据，并保留风险可能性及披露日期。还将“证据不足时直接回答可为空”与既有验证器要求非空中文解释的冲突对齐，允许必要的 filing 日期限定。JSON Schema、证据打包、引用映射、模型客户端和前端均未改动。

离线捕获确认：新旧请求的用户问题、10 个 E 窗口及顺序、证据字段、用户消息字节、JSON Schema、`stream=false`、`think=false` 完全相同，仅系统提示词不同。候选提示 SHA-256 为 `3d8629bc3fd3eb82e87a60d48a32d2152d1cf99e549c5d14a5e4472024bec09d`；原提示为 `1d9b836db04b1ba880527844a1771e1ec651c675b3cc1afe698ce35dd71265a9`。旧请求未显式记录 temperature、seed 等运行时设置，其有效值无法确认。

本机 `qwen3:4b` digest 与冻结样本相同：`359d7dd4bcdab3d86b87d73ac27966f4dbb9f5efdfcc75d34a8764a09474fae7`。**仅新增一次**本地回答调用；已有结构化输出验证通过，模型报告耗时 **15,134 ms**，记录包装耗时 **15,143.527 ms**。SEC、Alpha Vantage 和模型下载的新请求均为 0。通过 JSON 与引用 ID 验证不等于事实和引用语义得到验证。

## 双维度初审

新回答拆成实际存在的 9 条最小事实主张，其中 7 条充分支持、2 条部分支持；57 组“主张—引用”中，28 组支持、25 组部分支持、4 组不支持。旧冻结回答按其第二版口径为 11 条主张，8 条充分支持、3 条部分支持；66 组引用关系中，30 组支持、17 组部分支持、19 组不支持。**拆分口径和分母不同，不能把这些数字直接当作质量提升率。**这些都是 Codex 初审，人工确认状态仍为**待用户复核**。

本次新回答仍有以下具体问题：

- 直接回答附上全部 E1–E10，并称风险在申报中“反复强调”；多份历史披露可确认，但窗口未提供重要性或强调程度的比较依据。
- 第三方制造与组装仍错配 E8；E2、E5 才直接支持该事实。新版去掉了旧版同一要点上的 E9，但问题没有消失。
- 组件供应的要点仍附上只谈产能可用性的 E6、E9；具体供给、组件或产能风险仍被扩大成整体供应链不确定性。
- *manufacturing lead times* 仍被表述为“制造周期”；建议使用“制造提前期较长”。历史要点缺少逐项日期限定，不能自动当成当前状态。
- 新增“提前备货”要点有 E6、E9 直接支持，但它使回答偏离本题核心风险；产能可用性虽有窗口支持，仍未作为独立风险准确呈现。旧版已有的需求错估、制造提前期、组件和第三方制造主题没有整体被删除。

这份开发样本已参与提示词设计，只有一次新生成，不能排除随机性，也不是独立测试集、系统准确率或总体改进证明。由于引用堆叠和范围扩大未解决，且出现新的无依据概括，候选提示词**未保留在默认产品路径**；旧提示词继续使用。回退意味着旧提示中“证据不足时直接回答可为空”与现有验证器要求非空中文解释的文案冲突仍未修复；本轮不得将候选文案修复算作已上线。本轮不继续调提示词或追加模型调用。原始输出保持不变，不为使对照好看而改写。
