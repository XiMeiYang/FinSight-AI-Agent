# 本地 SEC 研究记录与历史回看

本轮在现有单用户、仅监听本机的 SEC 证据检索与可选回答应用中，增加独立的研究记录保存。它保存一次请求**实际生成**的回答和当时送入模型的全部证据窗口；历史回看直接读取本地数据库，不重新检索或调用模型。这里的“研究记录”不是完整财务研究报告，也不代表事实已经审计或人工确认。

## 使用边界

- 使用 Python 标准库 `sqlite3`。默认数据库为 Git 忽略目录 `.local_data/research/sec-research-records.sqlite3`；可通过 `--research-record-db` 指定本机专用目录下的路径。新建目录与数据库分别使用 `0700`、`0600` 权限；自定义的既有父目录若不是 `0700` 会安全拒绝，不擅自改变其权限。数据库包含真实问题、回答和 SEC 片段，不能提交 Git 或向公开日志输出。
- 服务端在生成回答时保存记录；浏览器只提交证券、问题和检索条件，不提交可被视为可信数据的答案或证据。
- 回答生成、记录保存、人工复核是三个独立状态。通过 JSON 结构与引用映射校验，不等于事实正确；新记录默认尚未人工复核。Evidence Auditor 仍是独立、暂停接入的实验。
- 本轮不改变回答提示词、检索算法、索引、SEC 语料或审计器，也不增加 SEC、行情或模型下载请求。

## 保存内容与接口

每条记录包含服务端生成的 ID、UTC 创建时间、股票代码、问题、检索过滤条件和可得的数据截止时间。详情保存最终展示的回答、回答状态、引用映射、**实际入模的全部证据窗口**（包括未被引用的窗口），以及窗口对应的 chunk、accession 和 SEC Archives 来源。模型名称、可得 digest、提示词哈希、调用次数、耗时和可得的语料/索引指纹也随记录保存；缺少的元数据保持缺失，不推测。记录有格式版本和内容哈希，用于发现损坏或不兼容数据；哈希只验证保存内容完整性，不证明金融结论正确。

- `GET /api/research-records?symbol=NVDA&limit=20&offset=0`：分页列表，可按股票筛选，显示问题、时间与状态。
- `GET /api/research-records/{record_id}`：保存的回答和当时证据。未知 ID 返回 404；损坏或不兼容记录明确报错。
- `POST /api/sec/answer`：原有回答接口增加 `research_record` 保存状态。保存失败时仍返回已生成回答及“未保存”状态，不重新调用模型。生成失败可保留最小失败记录，不伪装为成功回答。

网页“研究记录”页面可查看列表与详情；引用跳转只定位**该条记录**保存的 E 编号证据。页面明确提示“事实内容尚未人工核验”。即使之后更换索引，历史详情仍读取当时保存的窗口。

## 本机启动

在已具备本地 100 份 SEC corpus、匹配 BM25/Dense 索引、BGE 缓存及应用依赖的机器上，从仓库根目录运行：

```bash
PYTHONPATH=src .local_data/venvs/sec-embedding/bin/python scripts/run_local_app.py \
  --bm25-index .local_data/rag/indexes/sec-bm25-2026-10-26-100 \
  --dense-index .local_data/rag/indexes/sec-bge-small-en-v1.5-2026-10-26-100 \
  --corpus .local_data/rag/corpus \
  --model-cache .local_data/models/hub \
  --model-revision 5c38ec7c405ec4b44b94cc5a9bb96e735b38267a \
  --enable-ollama --ollama-model qwen3:4b \
  --host 127.0.0.1 --port 8000
```

打开 <http://127.0.0.1:8000/>，在“SEC 证据检索”里主动生成一次回答，再进入“研究记录”打开它；刷新页面或重启同一数据库的应用后仍可回看。未启用 Ollama 时，已有记录仍可查看，但不能生成新回答。默认路径和本地真实索引、语料、模型缓存均不随仓库分发，其他机器须先确认实际产物。

## 验证与限制

测试使用合成数据和 fake client，覆盖保存后重开、分页、筛选、损坏记录、引文隔离、未引用入模窗口、保存失败不重试模型、历史读取零检索/零模型调用，以及文本安全。

2026-10-30 本机验收：使用已保存的 100 份 SEC 语料和匹配索引，浏览器检索 NVDA 后主动生成一次本地 `qwen3:4b` 回答；页面报告生成耗时 **14,500 ms**、本地模型调用 **1 次**，随后显示“回答已保存为研究记录”。SQLite 记录中保存 **10 个实际入模窗口**，两个索引 manifest 的 SHA-256 均非空；目录和数据库权限分别为 `0700`、`0600`。关闭应用并以同一数据库重启后，网页历史列表和详情仍展示原回答与 10 条证据；点击该记录的 E1 引用可滚动定位到本条证据。重启后仅回看时 `/api/health` 报告本进程模型调用 **0 次**。本轮未新增 SEC、Alpha Vantage 或模型下载请求。回答内容**尚未逐条事实核验**，以上只证明本机一次保存与回看链路可用，不证明回答可靠或长期稳定。

本地 SQLite 仅服务当前 loopback 单用户场景，没有用户账户与跨用户隔离、云端同步、长期备份或迁移、完整研究报告、自动审计和人工标注工作流。历史保存不改善已有回答的事实质量，也不实现自选股、日报、多 Agent、邮件或部署。
