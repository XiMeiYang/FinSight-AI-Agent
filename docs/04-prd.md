# 产品需求文档（PRD）

状态：需求初稿；功能已确定，验收细节为设计建议，量化门槛待确认。

## 产品定位与已确定场景

该项目主要用于数据分析和 AI 产品经理方向的求职作品集，需要同时展示 Python、SQL、数据分析、金融分析、RAG、多 Agent、工具调用、记忆、评测、监控、产品设计和完整项目落地能力。

目标用户：关注美股但缺乏时间完成每日信息收集和系统分析的个人投资者，以及需要辅助完成金融研究的学习者。

1. 用户现场输入股票代码或公司名称，系统立即完成行情、技术面、基本面、新闻情绪、行业、宏观和风险分析。
2. 用户建立自选股列表，并为每只股票配置关注方向、涨跌幅阈值、成交量阈值和报告频率。系统进行分钟级异动监测，并在每日收盘后自动生成完整研究报告，通过系统消息和邮件发送。

## 已确定的 12 个核心模块

1. 股票搜索与即时分析；
2. 自选股管理；
3. 行情和异动监测；
4. 金融财报与公告RAG；
5. 多Agent协作分析；
6. 多头和空头交叉辩论；
7. 风险审查与证据校验；
8. K线、财务、新闻情绪和行业对比可视化；
9. 每日收盘报告与邮件推送；
10. LLMOps监控；
11. 5个交易日、20个交易日自动复盘；
12. Agent评测体系；

## 已确认 MVP 边界

第一阶段只做美股；采用免费或低成本数据，允许行情延迟 5–15 分钟。MVP 仅正常交易时段分钟检查，暂不监控盘前盘后，不追求毫秒级实时。每名用户可设合理自选股上限，数值待数据限额确认。保留即时查询、持续监控、每日收盘报告、系统内报告/消息和邮件，复盘为 5/20 个交易日。

## 核心流程

用户搜索并选择准确证券 → 立即发起分析 → 查看证据、分歧与风险 → 加入自选股 → 接收异动与收盘报告 → 查看历史 → 在第 5/20 个交易日查看自动复盘。

## 功能与验收

| 编号 | 功能 | 验收条件 |
| --- | --- | --- |
| F01 | 股票搜索与立即分析 | 支持代码、公司名称或自然语言输入，识别意图、证券及时间范围并显示交易所及类型；选定后立即执行请求所需的行情、技术面、基本面、新闻情绪、行业、宏观和风险分析并展示进度，综合研究覆盖七维；无匹配、歧义或超时有明确状态 |
| F02 | 自选股 | 可添加、移除和查看；支持分组和关注理由；每股可配置财报/新闻/行业/风险重点、涨跌幅阈值、成交量阈值及日报/周报偏好并持久保存；防重复，按用户隔离；移除后停止后续监控订阅，历史保留策略待定 |
| F03 | 分钟级异动监测 | 仅在美股正常交易时段按分钟级周期检查可用行情、价格/成交量/波动率异常及新闻公告，生成异常简报；显示事件时间、采集时间和延迟；过期数据不产生伪实时告警 |
| F04 | 收盘自动报告 | 按交易日历及收盘时间为用户自选股自动生成完整研究报告；支持逐股报告频率配置，其与每日收盘报告的关系待细化；列明缺失项；同一用户、交易日和版本不重复生成 |
| F05 | 系统消息与邮件 | 已授权用户可配置渠道；记录投递状态；失败可有限重试并去重；未配置邮箱不伪报发送成功 |
| F06 | 金融 RAG | 支持财报、公告与历史报告自然语言问答；检索链路采用待验证的建议方案，返回可定位证据并核验引用；每个金融结论关联数据和来源；按分析截止时间过滤；无证据时明确不足 |
| F07 | 多 Agent 协作 | 根据任务复杂度路由到必要角色，不强制所有请求调用全部暂定 Agent；多头、空头独立产出初稿并互相质疑，风控审查，裁判形成综合结论；分歧保留，允许弃权 |
| F08 | 历史报告 | 可按证券、日期和类型查看；保留证据快照、配置及版本；修订生成新版本 |
| F09 | 5/20 个交易日自动复盘 | 保存每次判断；到期产生关联原判断与报告的复盘记录；分别展示原判断、观察数据和误差；数据不足标记待补充 |
| F10 | 可视化 | 展示 K线、财务、新闻情绪和行业对比；各图显示时间、来源、单位与缺口，不能用无数据图形伪装结果 |
| F11 | LLMOps监控 | 可追踪各 Agent 的模型与提示版本、工具调用、耗时、Token、成本依据、失败和引用状态；门槛待实测确认 |
| F12 | 历史相似事件 | 使用历史相似事件验证当前假设，说明筛选依据、支持与反例；严格遵守 Point-in-Time，无样本则说明不足 |
| F13 | Agent评测与历史表现 | 提供离线评测，并按 Agent、事件类型、数据源统计历史表现，展示样本量、口径与限制，不虚构指标 |

## 分析与报告内容

证券身份、报告 ID、生成时间、数据截止时间、实时/延迟状态、行情、技术面、基本面、新闻情绪、行业、宏观和风险分析，历史相似事件证据，K线、财务、新闻情绪及行业对比可视化、多头观点、空头观点、风险约束、裁判结论、分歧、缺失数据和引用。模型判断不得伪装为事实；未经校准的置信度不能呈现为统计概率。

## 状态与异常

分析任务使用排队、运行、部分完成、完成、失败、取消等明确状态。来源部分不可用时，说明影响范围；关键数据缺失时不形成确定性判断。通知单独记录待发送、已发送、失败；供应商接收不等于用户已阅读。禁止用空值或零替代请求失败。

## 非功能与边界

数据溯源、用户隔离、可审计、幂等重试、调用成本记录为设计要求。现场输入后立即完成分析是已确定体验目标，具体耗时验收值待确认和实测，不擅自改为仅排队或异步报告。分钟级检查周期与源数据延迟分别呈现；允许免费或低成本行情存在 5–15 分钟延迟，不追求高频交易级实时性。所有分析显示数据时间和来源，历史分析与回测采用 Point-in-Time，不使用当时尚未公开的信息。收盘任务遵循美股交易日历、夏令时和提前收盘，不固定为北京时间某小时。

不接入真实券商账户、不执行自动或真实交易、不承诺收益，不虚构行情、新闻、财务数据和实验指标。当前阶段不做业务实现。

## 发布前待定

美股证券子类型、用户规模与自选股上限、分析响应时间、分钟检查周期及异常规则、告警冷却、收盘数据等待与报告时限、日报/周报生成及投递关系、数据保留、复盘起算及基准、置信度校准和评测门槛。正常时段限制、5–15 分钟延迟和 5/20 个交易日口径已确认，不再待定。所有决定同步 PROJECT_MEMORY.md。

## 暂定角色与已确认记忆要求

多 Agent 协作能力已确认，角色拆分暂定为 Router/Planner、行情、基本面、新闻事件、行业与宏观、Quant、多头、空头、风控、Evidence Auditor、裁判、报告和复盘；按任务调用，职责见技术方案。

多轮记忆保存会话中的证券、时间范围与任务上下文，支持追问；持久保存用户配置、每次判断和证据及版本，关联报告与复盘。记忆读取遵守用户权限与截止时间，不能把历史模型输出当作原始事实。

## 即时助手：查询与路由要求

示例输入包括“NVDA”“Apple”“分析微软最近为什么下跌”“对比Google和Microsoft的盈利能力”“阅读Tesla最新财报的主要风险”。这些只是需求示例，不代表已获取行情或已生成分析。

识别意图 → 解析股票及时间范围 → 获取行情财务 → 检索新闻公告财报 → 调用分析工具 → 必要 Agent 分析 → 综合研究时进行多空证据辩论 → 风险与证据审查 → 裁判综合 → 输出图表、数据、来源、置信度与限制。支持基本面、财务指标、估值、技术指标、新闻事件、行业表现、宏观因素、股票对比、财报解读和异动原因。数字必须通过 Python 或确定性计算工具；简单事实查询不强制全部步骤或角色。

## 监测、可视化与报告细化

监测覆盖涨跌幅、成交量、波动率、行业联动、重要新闻、公司公告、财报发布日期及数据源异常。告警包含阈值、冷却、重复合并、新鲜度检查、有限重试及降级机制，并显示原因、数据时间、置信度和原始来源。5–15 分钟延迟不是实时事件发生时刻，不能误导用户。

计划可视化包括 K线、成交量、移动平均等技术指标、财务指标趋势、收入与利润、新闻情绪、行业和大盘对比、自选股组合表现、多空观点、风险等级、历史报告和判断复盘。自选股组合不代表真实账户持仓，权重和收益口径待确认。

每日收盘报告至少包含：自选股整体表现、逐股涨跌、成交量及波动异常、大盘与行业对比、当日新闻公告、基本面变化、多头与空头观点、风险、综合判断、后续观察指标、数据截止时间、数据及引用来源、系统限制。报告归档后按已授权配置通过邮件发送，首版支持系统内查看，其他通知方式后续扩展。

每次报告还应保存当时可获取的数据、主要判断、正反证据、置信度、风险、生成时间、截止时间，以及模型、工具和来源版本。置信度须说明依据和局限，未校准时不能当作真实概率。日报/周报选项已确认，每日收盘生成也已确认；两者对生成与发送的关系需明确，不能自行取消任一要求。
