# 模拟访谈记录 001

> **状态说明：这是模拟访谈材料，用于研究流程和提纲演练，不是真实用户访谈，不可作为用户需求已验证的证据。其中时间、使用习惯和回答均为模拟内容。**

## 参与者画像

- 身份：计算机相关专业学生
- 美股关注经历：约 2 年
- 关注对象：英伟达、苹果、微软、特斯拉等科技公司
- 常用工具：Yahoo Finance、TradingView、公司官网、财经新闻平台
- 使用习惯：偶尔查询股票和阅读财报，不进行高频交易
- 个人信息、真实持仓及收益：不记录

## 访谈记录

**访谈者：最近一次研究美股是什么时候？研究了什么？**

参与者：上周看了英伟达。我看到股价波动比较大，想知道是公司自身的消息，还是整个科技板块都在调整。

**访谈者：你是怎么查的？**

参与者：先在 Yahoo Finance 看当天走势和成交量，然后去 TradingView 看 K 线。之后搜索相关新闻，如果看到财报、产品发布或监管相关内容，再到公司官网找原文。

**访谈者：哪一步最麻烦？**

参与者：不同信息分散在多个地方。行情、新闻和公司公告之间需要自己切换，而且新闻标题不一定能解释股价变化。最后看了很多内容，也不确定哪一个才是主要原因。

**访谈者：整个过程大概需要多久？**

参与者：简单看一下可能十几分钟；如果要确认新闻来源、看行业走势和公司公告，可能要四十分钟以上。这个时间只是我自己的估计，没有实际计时。

**访谈者：你会核对 AI 或财经新闻给出的结论吗？**

参与者：重要结论会核对。例如有人说股价下跌是因为某条新闻，我会看新闻发布时间。如果股价先跌、新闻后发布，那就不能直接把它当成原因。但平时没有时间每条都查。

**访谈者：你阅读财报时有什么困难？**

参与者：主要是财报太长。我一般想找收入增长、利润率、各业务表现和管理层指引，但不知道内容具体在哪一页。有些总结只说结果，不告诉我原文位置，我还是不太放心。

**访谈者：你会持续关注几只股票吗？**

参与者：会，大概五到八只。但不是每天都看。有时看到股价已经大幅波动，才知道当天发生了事情。

**访谈者：你现在使用价格提醒吗？**

参与者：偶尔使用简单的涨跌幅提醒，但提醒只告诉我涨了或者跌了，不告诉我成交量是否异常，也不解释可能相关的新闻和行业变化。

**访谈者：如果系统进行分钟级监测，你会需要吗？**

参与者：可能需要，但不能提醒太频繁。如果同一只股票连续波动，最好合并成一条。行情延迟五到十五分钟我能接受，因为我不是做高频交易，但必须把延迟写清楚。

**访谈者：每天收盘后自动生成报告有用吗？**

参与者：有一定作用，尤其是一次关注多只股票的时候。但我不想每天收到很长的报告。最好先给一个简短概览，再让我展开查看详细分析。邮件不一定每天发，重要异动可以发，普通情况放在系统里就行。

**访谈者：多头和空头分别分析，你觉得有用吗？**

参与者：有用，因为自己看股票时容易只找支持原来想法的信息。不过如果只是两个 AI 互相说观点，没有数据和来源，那只是把一份总结变成两份总结。最好能看到双方分别依据什么。

**访谈者：你会查看五个或二十个交易日后的复盘吗？**

参与者：如果操作简单，我愿意看。但我更关心当时的判断依据是否合理，而不只是之后股价涨没涨。有些判断方向错了，可能是遗漏信息；也可能逻辑没错，只是市场出现了新事件。

**访谈者：哪些工作不希望完全交给 AI？**

参与者：最终判断不能完全交给 AI。AI 可以收集信息、计算指标、提醒风险，但不能直接告诉我一定应该买或者卖。重大新闻和财务数字最好能点开原始来源。

**访谈者：如果只能保留三个功能，你会选择什么？**

参与者：

1. 自选股异动监测和原因摘要；
2. 带原文位置的财报问答；
3. 收盘后的自选股简报。

完整的多 Agent 过程可以放在后台，我主要关心结论、证据和风险。

## 初步整理

| 痛点假设 | 模拟结果 | 说明 |
| --- | --- | --- |
| 信息分散、切换工具耗时 | 有初步支持 | 行情、图表、新闻和公告分布在不同平台 |
| 难以判断股票异动原因 | 有初步支持 | 新闻时间可能晚于价格变化，需要时间核对 |
| 普通 AI 缺少来源 | 有初步支持 | 重大结论需要原始出处 |
| 财报太长、定位困难 | 有初步支持 | 关注关键指标和管理层指引的原文位置 |
| 持续盯盘成本高 | 有初步支持 | 经常在波动后才知道事件 |
| 用户希望频繁收到提醒 | 出现反证 | 提醒过多会造成打扰，需要合并和冷却 |
| 用户希望每天接收完整邮件 | 出现反证 | 更偏好系统内概览，邮件只发送重要内容 |
| 多 Agent 天然提升体验 | 信息不足 | 用户主要关心证据和结果，而不是 Agent 数量 |
| 历史复盘具有价值 | 有初步支持 | 需要分析判断过程，不能只用股价涨跌评价 |
| 延迟行情不可接受 | 出现反证 | 非高频场景下可接受 5–15 分钟，但必须标明 |

## 从模拟访谈得到的产品提示

- 报告采用“简短摘要＋展开详情”，不要默认展示超长分析。
- 告警增加冷却和事件合并，避免连续推送。
- 每个重要结论提供数据时间和原始来源。
- 多 Agent 属于分析方法，不应成为界面噱头。
- 复盘要区分“原判断质量”和“后续新事件影响”。
- 邮件推送频率应允许用户设置，系统内仍可每天保存报告。
