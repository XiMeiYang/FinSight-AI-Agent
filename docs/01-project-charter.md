# 项目立项

状态：立项初稿；产品范围依据用户已确定决策，其余为待验证规划。

## 背景与目标

项目名称：《基于大语言模型与多智能体协作的智能金融分析 AI Agent》；英文产品名：FinSight AI Agent。

该项目主要用于数据分析实习、AI 产品经理实习及数据产品/金融科技岗位的求职作品集，需要同时展示 Python、SQL、数据分析、金融分析、RAG、多 Agent、工具调用、记忆、评测、监控、产品设计和完整项目落地能力。

目标用户：关注美股但缺乏时间完成每日信息收集和系统分析的个人投资者，以及需要辅助完成金融研究的学习者。

围绕美股研究建立从主动查询、自选股跟踪到收盘总结和事后复盘的连续工作流。以金融 RAG 提供证据，以多头、空头、风控、裁判协作呈现分歧和风险，帮助用户检查分析依据。

## 范围与交付

第一阶段包括股票搜索与七维即时分析、逐股配置自选股、分钟级监控、财报公告 RAG、按任务复杂度路由的多 Agent 协作、多空交叉辩论、风险与证据校验、行情/财务/情绪/行业及判断复盘可视化、收盘报告与系统消息及邮件、LLMOps、历史判断保存、5/20 个交易日复盘和 Agent 评测。具体模块见 PRD。当前交付仅为项目规范、八份规划文档和五份 Skill 定义。

不纳入真实券商接入与真实交易。不以收益保证、无人值守投资决策或尚未授权的市场扩展作为目标。

## 成功标准

后续系统应能让用户追溯关键结论，识别数据时间与缺口，可靠接收已授权通知，并对原始分析进行不泄漏未来信息的复盘。功能验收见 PRD，量化门槛在数据源与成本验证后确定；当前不声明性能或准确率。

## 风险与依赖

| 风险 | 应对规划 |
| --- | --- |
| 实时行情许可或成本超出预算 | 先核验授权与延迟，不将延迟数据包装为实时 |
| 模型幻觉或同质化辩论 | 引用检查、独立初稿、证据不足时弃权 |
| 外部数据不稳定 | 有限重试、数据新鲜度状态、部分报告 |
| 多 Agent 延迟与费用 | 调用预算、缓存及受控辩论轮次 |
| 复盘引入未来信息 | 保存当时证据快照与不可变原报告 |

预算、工期、人员和部署环境尚未确定。阶段完成以可核验交付和验收为准，不编造成本与上线日期。

## 已确定创新与作品集交付目标

1. 每个金融结论都必须关联数据和来源。
2. 多头和空头 Agent 互相质疑。
3. 使用历史相似事件验证当前假设。
4. 历史分析采用 Point-in-Time 机制，防止未来数据泄漏。
5. 保存每次判断，并在 5 个交易日、20 个交易日后自动复盘。
6. 统计不同 Agent、事件类型和数据源的历史表现。

后续作品集应保留 Python 数据处理、SQL 查询与分析、金融指标口径、RAG 与工具调用轨迹、记忆与复盘、评测和监控记录，以及产品调研、原型、Beta 反馈、迭代和部署证据。当前仅规划这些交付，不宣称已有用户、效果或部署成果。

实施流程：Problem Discovery → 用户和痛点验证 → 竞品分析 → 用户访谈或问卷 → PRD → Prototype → Technical Design → MVP → Evaluation → Beta真实用户验证 → 用户行为和反馈分析 → Iteration → 部署上线 → 持续Monitoring。

## 已确认的开发者定位与交付边界

开发者为软件工程本科背景，计划于 2026 年 9 月至 2027 年 11 月就读香港大学计算机科学硕士、面向金融计算学习；已有多模态冷启动商品推荐系统及全流程开发经验，详细技术经历见项目记忆，不直接继承为本项目选型。

能力定位是“数据分析主轴、技术基础、产品加分、AI Agent 差异化”，不以纯算法工程师或量化交易员为目标。利用 AI 编程工具，通过拆解、审查、测试和学习完成真实可用、可上线、可量化评测的核心作品。

项目不能只是股票评论、Excel 自动画图、单个 API 包装、次日涨跌预测或复制 TradingAgents 等开源项目。需要展示意图与路由、多轮记忆、工具调用及真实用户验证、Python/SQL 分析和数据驱动迭代；相关开源研究必须说明借鉴范围和自身贡献，不预设竞品结论。

MVP 已确认：仅美股正常交易时段，无盘前盘后；免费或低成本数据允许 5–15 分钟延迟；自选股上限待数据额度核验；两大场景、每日收盘报告、系统内与邮件、5/20 个交易日复盘均保留。系统仅作研究辅助，不提供确定性投资建议。
