# Prototype 原型设计

状态：原型已完成；仅用于离线流程演示和下一步可用性测试，未连接 API、未发送系统消息或邮件。NVDA、AAPL、MSFT 均为明确标注的 synthetic Mock Data，不代表真实行情或研究结论。已完成 n=3 真实访谈的匿名聚合，但尚无原型可用性结果。

## 目标与边界

原型主要验证 P0 核心路径：用户输入股票代码后能否理解“搜索 → 分析执行 → 分层报告 → 证据与导出”。自选股、收盘报告和历史复盘保留为后续功能入口。原生 HTML/CSS/JavaScript 实现，无依赖、外部字体、图片或网络请求，中文桌面优先并适配窄屏。

本原型不模拟真实 API、券商、交易、收益、实时行情或邮件投递。数据截止时间、15 分钟延迟、来源状态和失败/降级状态均为界面演示。5/20 个交易日复盘保留待实现入口；复盘起点、基准、复权口径仍待确认。当前原型提供基础 Mock K 线和 Excel 导出预览入口：导出预览必须展示来源、时间、币种、单位、延迟和缺失说明，并明确数据来自已保存快照，不由 LLM 临时生成数字。视觉采用左侧深蓝导航与浅色工作区的专业研究工作台风格。

## 信息架构与页面

- 搜索与即时分析：首页提供搜索框、研究路径和 Mock 标的结果；可进入分析执行。
- 分析执行：展示易理解的数据处理步骤：读取已保存行情、获取 SEC 文件、提取财务事实、检查时间和来源、生成摘要、准备导出；完成后查看单股报告。主界面不展示复杂 Agent 内部过程。
- 单股研究报告：展示行情概览及事实、计算、推断、风险四层内容；来源卡片可展开。
- 我的自选股：展示状态、查看报告、加入和移除自选股。
- 收盘报告：保留后续功能占位，不展示虚构的投递成功或组合结果。
- 历史复盘：明确显示 5/20 个交易日待实现，不填充虚构结果。
- K线与导出：展示基础 Mock K 线、数据状态和复权说明；导出入口展示计划工作表和字段元数据。真实行情 K 线和文件生成仍未实现。

导航按钮、分析、查看报告、加入/移除自选股和来源卡片均有可点击反馈。报告中演示正常、证据不足、数据延迟和缺失状态；后续页面入口明确标注未实现。分析步骤页提供处理阶段展示，不代表后台任务已实现。

## 主路径与交互流程

当前主路径为：`搜索 NVDA → 数据处理步骤 → 报告 → 日线概览 → SEC 事实与来源 → 证据展开 → K 线 → Excel 预览 → 运行记录`。

1. 首页默认显示 `NVDA`，也可输入 `AAPL` 或 `MSFT`，点击“开始分析”。
2. 查看面向用户的数据处理步骤，不显示复杂 Agent 执行队列，也不伪造进度百分比。
3. 点击“查看演示报告”，检查日线概览、Mock K 线、SEC 模拟事实和数据缺失提示。
4. 点击来源按钮打开来源卡片，点击“展开证据”查看事实、计算、推断和风险分层。
5. 点击“预览 Excel 导出”和“查看运行记录”，确认两者均为原型预览，不代表真实文件或后台任务。
6. 点击自选股、收盘报告和历史复盘，确认它们仅显示后续功能占位，并能返回搜索首页。

## Mock 边界与真实性

所有股票卡片都显示 `Mock Data`。代码内价格和涨跌幅仅为 synthetic 演示值；不应复制到报告、简历或金融结论中。页面不会调用网络，不会声称数据实时，不会发送邮件，也不产生真实交易建议。

## 可用性测试任务（待真实用户执行）

1. 搜索并分析 NVDA：找到 NVDA，启动分析并打开演示报告，记录完成时间、误解点和是否发现 Mock/截止时间。
2. 找到一条结论的证据来源：在报告中打开“事实来源”或“SEC Filing Mock”来源卡片，说明是否理解原文定位仍是演示。
3. 展开证据：检查报告的事实、计算、推断和风险分层，说明是否能找到来源和缺失状态；多头、空头及其他 Agent 过程当前不在主界面。
4. 查看后续功能入口：点击“加入自选股（后续功能）”或导航中的自选股/收盘报告，确认页面明确标记为后续功能，不把占位页面误认为真实持久化。
5. 查看自选股、收盘报告和历史复盘入口，确认它们显示后续功能占位和返回搜索首页按钮。
6. 在 NVDA 报告中识别数据延迟、部分完成和证据不足，并说明下一步行动。
7. 查看未来复盘：找到 5/20 日复盘入口并说明当前能否查看结果，确认待实现状态是否清楚。
8. 查看 K 线并打开 Excel 导出预览，确认来源、数据时间、币种、单位、延迟和缺失说明清晰，且没有把 Mock 数值当成真实结果。

当前没有原型任务成功率、满意度或效果结果；真实访谈的匿名聚合见[访谈记录](research/user-interview-synthesis-001.md)，不把访谈反馈或演示结果写成产品效果结论。

## 待验证问题

- 用户是否能在不阅读说明的情况下理解四类结论和来源卡片的关系？
- “分析执行”中的数据处理步骤是否帮助建立信任，还是增加理解成本？
- 用户期望的自选股配置字段、提醒频率和关闭入口是什么？
- 收盘报告的“生成”和“发送”是否应分开设置？邮件授权、退订和保留期限如何设计？
- 5/20 日复盘的价格锚点、基准、复权和缺失数据呈现方式待确认。

## 视觉改版记录（2026-09-22）

根据用户明确的界面偏好，原型改为左侧深蓝固定导航、浅灰主工作区、白色卡片和蓝色主按钮的专业研究工作台风格。此次只改变视觉层级、导航布局和响应式呈现，保留当前 P0 主流程、来源/证据/Excel/运行记录弹窗及后续功能占位；不代表可用性测试已经成功，也不改变产品优先级。
