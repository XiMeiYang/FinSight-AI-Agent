# 开发计划

状态：实施流程已确认；各阶段工作拆分与验收细节为规划，人员、工期、预算和数值门槛待定。当前完成了官方资料竞品案头调研，仍未执行真实用户访谈、产品/API 实测、开发、实验或部署。

## 已确定的实施流程

Problem Discovery → 用户和痛点验证 → 竞品分析 → 用户访谈或问卷 → PRD → Prototype → Technical Design → MVP → Evaluation → Beta真实用户验证 → 用户行为和反馈分析 → Iteration → 部署上线 → 持续Monitoring。

下表严格沿用这一顺序。提前建立 PRD 或技术方案文档不代表已完成前置用户研究。

| 阶段 | 规划工作 | 后续完成依据 |
| --- | --- | --- |
| Problem Discovery | 围绕美股个人投资者和学习者明确问题与研究假设 | 问题定义、证据来源和待验证假设 |
| 用户和痛点验证 | 初步确认场景与需求，不擅自改变已确定定位 | 有来源的初步验证记录 |
| 竞品分析 | 按统一维度核验产品能力及限制 | 官方依据、核验日期与对比记录 |
| 用户访谈或问卷 | 访谈真实研究行为、逐股配置及报告需求 | 匿名记录、样本说明与洞察 |
| PRD | 固化 12 个模块、两大场景与验收要求 | 可追溯需求和待确认细节 |
| Prototype（原型） | 搜索分析、自选股配置、图表、报告与复盘界面 | 原型及可用性反馈 |
| Technical Design（技术设计） | 暂定 Agent 路由、建议 RAG 检索链、工具调用、记忆、Point-in-Time 和数据方案 | 技术决策、数据契约与测试计划 |
| MVP | 在后续授权下分步实现可运行闭环 | 可演示功能及真实测试记录 |
| Evaluation | 执行 Agent、RAG、协作、安全、成本与复盘评测 | 版本化样本与可复现实测结果 |
| Beta真实用户验证 | 邀请真实目标用户体验并收集反馈 | 授权及匿名化反馈，不虚构用户 |
| 用户行为和反馈分析 | 以 Python、SQL 分析使用和质量数据及分组表现 | 可复现查询、分析和局限说明 |
| Iteration（版本迭代） | 根据证据改进体验与分析质量 | 变更依据及回归验证 |
| 部署上线 | 发布可使用系统 | 部署与实际访问验证记录 |
| 持续Monitoring（持续监控） | 观察 LLMOps、任务与数据质量 | 运行记录、故障恢复和监控证据 |

## MVP 内部实现拆分建议

这只是未来 MVP 阶段的开发顺序，不是删除产品模块，也不授权现在开始实现。

1. 可溯源离线样本、股票搜索和七维研究；按复杂度路由必要角色，验证建议 RAG 链路、工具调用、多空质疑、证据审计及风控裁判，不一次堆齐所有候选框架。
2. 接入核验后的合法数据源，建设逐股关注方向、涨跌幅阈值、成交量阈值及报告频率配置，保存每次判断与证据，并按 PRD 提供适用的行情、财务、情绪、行业与复盘图表。
3. 分钟级监控、收盘完整报告、系统消息及已授权邮件，验证延迟显示、日历、幂等和恢复。
4. 5/20 个交易日自动复盘、历史相似事件验证与按 Agent/事件类型/数据源统计表现。

工具调用追踪、记忆、Point-in-Time、真实性校验和 LLMOps 从首个闭环纳入，不在最后补做。已确认 MVP 边界见 PRD：仅美股正常时段、5–15 分钟延迟、两大场景、收盘报告与系统内/邮件、5/20 个交易日复盘。自选股上限及功能交付拆分待数据额度和前期验证后细化，不能将建议当成已批准的删减。
